## What this is

**Max** — an AI Slack teammate for NeuroGrowth, a single-file Node app (`index.js`, ~14.6k lines). Runs as a long-lived Node process on **Railway** (service `ng-pm-MAX`, auto-deploys from GitHub `main`). Slack Socket Mode. There is no sidecar process — `ghl-mcp/` was deleted 2026-08-24 (PR #117) after being confirmed dead.

- Repo: `neurogrowth-cr/ng-agent` on GitHub
- Runtime: Node ≥18, Slack Bolt, Claude Sonnet 4.6 via `@anthropic-ai/sdk`
- Entrypoint: `node index.js`

## Dash normalizer: GHL reschedule/cancel ingestion (2026-08-03, PR #20 MERGED + deployed)

dash repo `fix/ghl-reschedule-normalizer` → [PR #20](https://github.com/neurogrowth-cr/dash.neurogrowth.io/pull/20), merged to main (`dd92557`), Vercel production deploy succeeded 2026-08-04 00:11 UTC.

**What it fixes:** calendar-shape GHL payloads (no `type`, no `customData.ng_event` — sent by the "Neurogrowth Dashboard Webhook" workflow) were all skipped as `unknown_event_shape` (39+ rows), so rescheduled call times went stale in `revops_appointments`. Now they classify from `calendar.appoinmentStatus`, and a provisional `call_booked` flips to `ghl.call_rescheduled` when delivery history for the same `appointmentId` shows a different prior `startTime` (also catches GHL's booked-workflow re-fires on reschedule).

**Traps encoded in the fix (don't regress):**
1. `calendar.id` = the CALENDAR's id, not the appointment's — always use `calendar.appointmentId`.
2. Webhook `calendar.startTime` is NAIVE LOCAL time in `calendar.selectedTimezone`; API-hydrated rows store UTC. Both normalize paths convert via `naiveLocalToUtcIso()`; the history comparison uses raw payload startTimes (format-stable).
3. `upsertAppointmentFromEvent` used to null-wipe `setter_id`/`closer_id` when an event carried no owner fields — now only writes owners when non-null (or on insert). Protects leaderboard attribution.

**Data backfill (one-time, 2026-08-03):** 11 `revops_appointments.scheduled_start` rows corrected from delivery history (real reschedules that had never applied, e.g. Jul 28 → Aug 14). Side effect worth remembering: stale times made the Aug 3 DAILY CALL ROSTER say "no calls" when Ricardo Jiménez had a 2 PM call that day.

**Verification:** 222/222 vitest pass (5 new tests + fixture `calendar-shape-update.json`); tsc clean on touched files; next real reschedule should show `normalized_event_type='ghl.call_rescheduled'`, `status='applied'`.

## Appointment-alert hardening (2026-08-04): booked dedupe + delivery retry

**Booked-alert dedupe** — a reschedule no longer double-alerts (GHL re-fires the booked workflow on reschedule). Make scenario 5148796 now calls Supabase RPC `ng_register_booked_alert(appt_id)` (PostgREST, anon key, fail-open) before its Slack module; the Slack post is filtered out only when the RPC returns literal `false` (appointment already alerted). Dedupe state lives in `ng_appt_slack_alerts` kind='booked' (backfilled for all pre-existing GHL appointments). CAPI event_ids in that scenario fall back to `calendar.appointmentId` when the `appointment_id` merge tag is empty.

**Delivery retry (outbox)** — cancel/reschedule alerts from `ng_appt_change_notify()` no longer fire-and-forget: the trigger writes `ng_alert_outbox` (body + pg_net request_id) and pg_cron job `ng-alert-outbox-sweep` (*/5 min, website project) marks 2xx delivered, retries failures/timeouts/lost responses (≤6 attempts over 48h), purges rows >14d. A Make outage now delays alerts instead of losing them. Monitor: `select * from ng_alert_outbox where not delivered`.

**iclosed_* migration debt** — verified CLOSED by the post-cutover truth pass; remaining `iclosed_*` code refs are legacy-row reads + the frozen `getNonFlywheelCallIds` memo (deletable ~2026-11-20).
